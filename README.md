## 它是什么

这是在 Linux 终端中输入文字的聊天室，不是微信小程序。一个进程当服务器，负责接收和转发消息；其他进程当客户端，负责输入和显示消息。同一个程序通过启动参数选择角色。

初版包含：TCP 连接、最多 16 个客户端群聊、自动用户编号、加入和退出提示、`/quit` 退出。自己发送的内容也会由服务器回显。没有登录、私聊、聊天记录、文件传输或加密，适合可信局域网内的课程演示。教师是否接受这个范围仍需确认。

## 拿到开发板后的第一步

先确认能打开鲁班猫的 Linux 终端，再执行：

```sh
uname -m
command -v gcc
```

第一条查看架构，第二条查找编译器。如果第二条没有结果，先记录系统版本与网络情况，再决定如何准备编译环境；不用急着安装软件。

## 编译

把 `chat.c` 放进开发板上的一个独立文件夹，在该文件夹打开终端：

```sh
gcc -std=c11 -Wall -Wextra -Wpedantic -O2 chat.c -o chat
```

这条命令应在 Linux 上执行。Windows 上编译出的普通程序不能直接当作鲁班猫程序运行。在板上编译能避免交叉编译工具链和架构不匹配问题。

如果已经有电脑上的 Linux 环境，同样进入源码目录执行该命令即可，无需开发板。有 make 时可以执行 `make`。

## 一块板子的演示方法

通过三个终端窗口进入同一块鲁班猫，每个窗口都进入保存 `chat` 的文件夹。SSH 连接时可以打开三个连接窗口。

终端 1 启动服务器，保持运行：

```sh
./chat server 8888
```

终端 2 启动第一个客户端：

```sh
./chat client 127.0.0.1 8888
```

终端 3 启动第二个客户端：

```sh
./chat client 127.0.0.1 8888
```

在终端 2 输入 `hello` 并回车，两个客户端都应显示 `[User 1] hello`。再在终端 3 输入 `hi`，两个客户端都应显示第二位用户的消息。

客户端输入 `/quit` 并回车退出，或者按 Ctrl+C。服务器按 Ctrl+C 停止。服务器关闭后，客户端应显示连接关闭。

`127.0.0.1` 表示当前这块板子，所以这种演示不需要第二块板子，也不需要外网。它验证的是本机多个进程之间的 TCP 通信；不能因此声称跨设备联网已验证。

## 跨设备演示（后续可选）

服务器继续运行在鲁班猫上，另一台 Linux 设备在同一局域网内编译此源码，再把客户端命令的 `127.0.0.1` 换成鲁班猫实际的局域网 IPv4 地址。可在板上执行 `hostname -I` 查看地址，注意一台设备可能有多个地址。Windows PowerShell 不能直接运行这个 Linux 程序。跨设备连接还取决于网络、路由与防火墙。

## 答辩需要理解的四件事

1. 服务器负责中转：客户端 A → 服务器 → 所有客户端。
2. Socket 是程序访问网络通信的接口。TCP 提供有序字节流，本程序用换行符区分每条消息。
3. `select` 让程序等待多个输入来源。服务器等待客户端，客户端同时等待键盘和服务器。
4. 开发板运行的是 Linux，程序调用 Linux 的网络接口，不涉及 GPIO 或传感器；是否需要硬件功能要以老师要求为准。

## 初版限制

消息正文每行最多 1023 字节，中文通常占多个字节。超长或含无效控制字符的消息会导致该客户端被关闭。客户端使用普通终端输入，收到消息可能打断尚未回车的文字显示。服务器采用简易阻塞发送并设置两秒发送超时，慢客户端仍可能暂时拖慢整个聊天室；这是课程初版，不适合公网服务。进程重启后不会保存用户或消息。
